## 本轮排版调整与验收目标

以下三项是本轮整合的排版调整方向，最终效果需按后面的浏览器步骤确认：

1. **区分文章标题与章节标题。** 文章标题保留更大的字阶，最高章节标题避免与其同样突出；苹果白主题主标题使用正文中性色。HTML 可适配标题视觉层级，Markdown 保留原文的 H1 / H2 / H3 语义层级。
2. **统一换行。** 正文、引用、Callout、步骤、标题和长链接采用一致的换行处理，在窄屏上保持可读性。
3. **代码字号跟随正文缩放。** 代码外层字号为 `max(13, round(bodySize × 0.9))px`，内层继承；保留适合公众号窄屏的 `pre-wrap` 和文本叶子节点行高处理。

## 自动检查

在 dev 目录执行：

```bash
npm test
npm run test:layout
npm run test:coverage
npm run typecheck
npm run build
```

`scripts/test.mjs` 使用已有的 esbuild 把 TypeScript 测试编译到临时目录，再运行 Node 内置测试工具，结束后清理该次生成的文件，不需要额外测试依赖。`test:coverage` 报告的是编译后的测试 bundle 覆盖率，不能表述为全部源码或产品功能覆盖率。

以上是检查命令，不是通过记录。实际测试结果以本轮执行输出为准。

## Chrome 验收步骤

1. 在 dev 目录完成构建，打开 `chrome://extensions`，核对扩展版本为 `1.2.1`，加载路径为 dev；停用 Documents 旧副本。
2. 点击 dev 扩展的重新加载按钮，然后刷新已打开的 Notion 页面，使内容脚本也更新。
3. 打开 [Arize 文章](https://app.notion.com/p/Arize-Agent-3fd9c4f5c8778084890fcfa4c6003d4a)，分别停留在顶部、中部和底部，再打开抽屉或刷新提取。三次预览应包含相同的第一段、全部章节和末尾来源，内容与顺序一致；扫描结束后恢复各自原阅读位置。
4. 切换包含标题区的现代主题，检查文章标题与章节字阶。用仅含 H2 / H3 的样例检查 HTML 视觉适配，并确认 Markdown 仍输出原始标题层级。
5. 使用长链接、多行引用、Callout、步骤列表和代码样例，在窄预览宽度下检查换行；点击 A+ / A−，确认代码与正文同步缩放。
6. 检查“重新排版”“清空排版”“取消配图”“移除配图”和风格提示词复制的显示与行为；生成内容的操作会使用配置的模型服务。
7. 复制包含粗体、代码、引用、Callout 的内容到公众号编辑器，检查实际行间距、换行和微信检测提示。自动化渲染测试不能代替公众号粘贴验收。
